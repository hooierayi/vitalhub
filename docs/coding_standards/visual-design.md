# 健康采集页面视觉设计

## 1. 适用范围

- 本文是新增或实质改版业务页面的默认视觉约束，依据 2026-08-19 提供的健康采集设计稿整理。
- 设计稿展示了采集任务、问卷、设备连接、实时预览、采集与分析结果等页面的共同语言；不把其中的具体文案、演示数据或未实现功能视为产品需求。
- 既有页面仅在需求明确时改版，避免为了统一视觉进行无关重构。

## 2. 尺寸与适配

- 以 **414dp 宽**作为设计稿还原、间距校准和截图验收的基准。
- 页面内容使用 `fillMaxWidth`、`weight`、`BoxWithConstraints` 或可滚动容器适配真实可用宽度；414dp 是基准，不是固定容器宽度。
- 横向内容默认使用 `FlowPage` 的 18dp 页面边距；双列/指标卡使用可分配宽度，避免固定卡片宽度导致窄屏裁切。
- 文本使用 `sp`，可变长度文案应考虑换行、截断或可滚动；底部操作区需避开系统导航栏和应用底栏。

## 3. 视觉语言与组件

| 元素 | 默认规则 | 优先复用 |
|---|---|---|
| 页面背景 | 浅灰蓝背景、白色内容卡片，信息层级清晰 | `VitalColors.Background`、`VitalColors.Surface`、`FlowPage` |
| 文字 | 深色标题、次级灰蓝说明、弱化辅助信息 | `VitalColors.TextPrimary`、`TextSecondary`、`TextMuted` |
| 卡片与选择项 | 细边框、约 8–13dp 圆角、规则留白；选中态使用浅青底与青色边框 | `InfoCard`、`ChoiceTile`、`SelectDot` |
| 主操作 | 默认使用青绿色；全宽、清晰且固定视觉重量 | `FlowButton(PRIMARY)`、`FullWidthButton` |
| 强调操作 | 蓝色仅用于需要额外强调的肯定操作；红色仅用于停止、结束等破坏性操作 | `FlowButton(BLUE)`、`FlowButton(DANGER)` |
| 状态反馈 | 成功/连接采用绿色或青绿色，告警与失败使用语义色；不得仅靠颜色表达状态 | `VitalColors.Success`、`Teal`、`Danger`、文本或图标 |
| 数据展示 | 指标采用紧凑卡片，波形/趋势保持足够留白与浅色网格 | `MetricCard`、`MetricRow`、`Waveform` |

现有颜色与组件定义位于 `core/common/src/main/java/com/smarthealth/vitalhub/core/ui/BaseFlowFragment.kt`。新增页面不得复制或分散重定义等价 token；需要新的稳定样式时，先评估是否扩展该公共层。

## 4. 页面结构

- 顶部由应用壳统一提供标题、返回和通知等能力；业务内容不自行复制应用级标题栏。
- 内容按“状态/摘要 → 主要任务 → 辅助说明或详情”组织，使用标题、卡片和分组间距建立层级。
- 问卷与步骤流使用进度、题号或步骤标识呈现当前阶段；选择控件提供明确的选中状态。
- 主操作放在用户完成当前步骤后可见、易触达的位置；同屏存在多个操作时，明确一个主操作，次要操作使用描边或低强调样式。
- 加载、空状态、连接失败与不可用状态需保持同一视觉语言，并给出用户可执行的下一步。

## 5. 交付检查

- 页面改动完成后，从实际入口走通关键用户路径，核对路由/参数、状态变化、主要操作和预期结果；同时验证与改动相关的空态、失败态或返回路径，不能只以编译通过代替功能验证。
- 在 414dp 宽度下检查页面边距、卡片宽度、文字层级、主操作和底部安全区。
- 在更窄实际宽度下确认无横向裁切、重叠或不可点击的底部操作；动态字体与长文案不应遮挡关键内容。
- 将运行截图或自动化测试结果作为可用的验证证据；无法验证时记录受限的设备、环境或外部依赖及其影响范围。
- 优先复用公共主题和组件；若新增颜色、间距、卡片或按钮变体具有跨页面价值，补充公共 UI 并更新本文。
