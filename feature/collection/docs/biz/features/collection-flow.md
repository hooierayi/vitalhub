# 首页采集流程

首页以同一个 `sessionId` 展示三个检查点：采集前问卷、数据采集、采集后问卷。
`CollectionFlowProvider` 由本模块以 MMKV 实现，并以 ARouter Provider 向首页、问卷和设备模块提供事件状态机。

- 前问卷提交后为 1/3；设备连接是数据采集内部瞬态，不推进首页检查点。
- 片段采集正常结束后为 2/3，并进入采集后问卷；后问卷提交后为 3/3 并返回首页。连续写卡当前没有结束入口，不通过连续记录页推进该检查点。
- 片段倒计时完成时，先停止可靠的设备帧 Sink 并等待在途帧，再由 `:foundation:file-protocol` 使用 dcm4che 封口本地 `.dcm`；随后通过 `RecordProvider` 将上传摘要写入本模块 Room 数据库，再推进流程和离开采集页。摘要包含本地记录标识、会话标识、记录时间、时长、最终 DICOM 路径、用户指纹和设备地址。新片段记录编号为 `CLIP-` 加 UUID 去连字符后的前 12 位十六进制字符，DICOM 文件名为 `<CLIP 记录编号>-<采集开始毫秒时间戳>-<三位分段序号>.dcm`；新连续记录编号使用相同随机后缀规则和 `CONT-` 前缀，未识别采集模式以 `REC-` 兜底，历史编号不迁移。记录库不创建设备表，记录页通过用户 Provider 解析用户名称并直接展示记录中的设备 MAC。
- 连续记录表示设备内部写卡操作，不创建本地上传文件，也不写入 `RecordProvider`。启动指令成功后将 App 生成的操作编号和开始时间写入 `DeviceInfo.record`；当前记录协议不保存结束时间，也不提供结束状态的持久化更新。Parcelable `DeviceInfo` 作为一个完整对象写入单个 `device_info` 键，不拆分字段。写入统一使用 `saveDevice(DeviceInfo)`；旧层仅保留设备对象、地址和名称读取接口。
- 实时预览是采集阶段的主页面。蓝牙连接成功后先正常进入实时预览，导航宿主在观察到“连接记录仪 → 实时预览”后旁路发送 `StartCollection`，不等待指令结果也不影响跳转；观察到“实时预览 → 连接记录仪”时同样旁路发送 `StopCollection`。从实时预览进入连续记录页时直接导航，不发送设备指令。页面通过 `DeviceProvider.getRecordInfo()` 恢复最近一次设备写卡记录的编号、开始时间和累计计时，但持久化记录不决定本次页面的按钮状态；每个新进入的连续记录页面初始底部始终为左侧“实时预览”、右侧“启动记录”。用户点击“启动记录”后按钮立即显示 loading 圈和“启动中”，并禁用重复点击；页面先发送 `StopCollection`，仅在设备确认停止采集成功后发送 `StartContinuous`。任一指令被拒绝、失败或任务取消后退出 loading；停止失败时不发送启动指令，按钮恢复为“启动记录”。本次启动成功后底部变为左侧“实时预览”、右侧“返回连接记录仪页面”：点击实时预览先发送 `StartCollection`，成功后才回到实时预览，失败则留在当前页；点击返回只断开蓝牙，不发送停止采集指令，断开成功后清空采集子页面并返回连接记录仪根页面。错误提示位于“APP断开后设备仍会继续记录”提示条下方，显示 3 秒后自动消失；新错误会重新开始计时。系统返回和标题栏返回仍回到实时预览。
- Provider 保存“待前问卷、待数据采集、待后问卷、已完成”四个检查点，并在首次收到 `CollectionCompleted` 时持久化真实完成时间；采集模块内的扫描、连接、断开、当前设备及连接事件统一由 `CollectionFlowActivity` 作用域的 `CollectionBluetoothProvider` 管理。项目设备筛选、可用设备选择、卡片顺序、流程提示及 `sessionId` 仍由采集流程首页自己的 `CollectionFlowHomeViewModel` 管理，Fragment 仅在渲染时组合两份状态。
- 四个检查点通过事件 reducer 推进。重复提交返回已处理结果并保持已有进度；非法或陈旧事件会被拒绝，不会把进度倒退。
- 应用恢复或硬件中断时保持“待数据采集”检查点，但再次进入时从连接页开始；采集后问卷中断保留 2/3。系统返回和标题栏返回均清空子流程并回到首页。
- AI 分析不属于这三步流程，后问卷提交不自动打开分析页。采集页以 `FROM_COLLECTION` 来源进入分析页，并继续透传 `flowEntryMode` 作为后问卷完成后的返回策略；分析页通过 `RecordProvider` 按唯一 `recordId` 读取刚完成的片段记录，仅持久化服务端 `analysisId`：为空时上传 DICOM，非空时直接查询，远端状态和 Markdown 结果不落库。`sessionId` 只用于后问卷和重新采集导航。首页历史记录则以 `FROM_RECORD` 来源进入，不显示后问卷入口。
- 首页底部按钮是从流程头部进入的主入口：无个人信息时显示“填写用户信息”，否则显示“填写采集前问卷”，并从前问卷开始串联流程。三张流程卡片直接进入对应业务；进入采集 Activity 前由应用层路由拦截器查询 `UserInfoProvider`，无完整资料时中断采集路由并转到用户填写页；完成后返回首页。直达入口完成后会更新对应卡片的完成态，但仅在命中当前检查点时推进线性检查点。
- 问卷答案按 `sessionId + questionnairePhase` 保存最新草稿和提交状态，重新进入时回显，重复提交覆盖同一份记录。
- 每个连接记录仪页面实例首次进入时，立即通过 `:foundation:bluetooth` 开始一次 BLE 扫描，离开页面时停止扫描。之后仅用户主动点击刷新时再次扫描；页面恢复前台、连接失败和扫描结束均不自动重启扫描。
- 页面默认仅显示本项目设备；没有连接历史时，第一个符合当前筛选条件的扫描结果作为可用设备。存在最近一次成功连接的设备时，可用设备优先恢复该设备，即使本次尚未扫描到。
- “可用设备”与“其他设备”是互斥分区，两者合并后构成当前筛选下的设备全集；“其他设备”区域独立滚动。连接成功后才推进采集流程，并通过 `:provider:device` 的 ARouter Provider 保存最近连接设备供下次恢复。
- 最近连接设备缓存当前 MAC 和设备名称；外部连接逻辑只提交新的设备地址和名称，`DeviceProviderImpl` 在地址相同时自动保留已有写卡记录，地址变化时不继承旧记录。恢复时通过 MAC 从蓝牙适配器重新取得系统设备并构造 `BluetoothGattDevice`。记录页直接展示记录表保存的 MAC。广播数据、RSSI 与扫描时间仅使用本次扫描结果。首次恢复时实时检查连接状态，缓存设备卡右上角显示“已连接”或“已掉线”，不使用缓存值推断当前连接状态。
- 扫描期间头部信号图标持续播放扩散动画，刷新图标持续匀速旋转且不可重复点击，扫描结束后停止；“其他设备”仅展示设备信息，连接操作只出现在“可用设备”。
- 可用设备连接成功后，连接按钮切换为红色“断开设备”按钮；连接和主动断开执行期间分别显示“连接中…”和“断开中…”及 loading 圈，并禁止重复点击、切换设备和重新扫描，操作结束后恢复。连接记录仪页的主动断开只断开蓝牙，不发送 `StopCollection`；主动或被动断开后恢复为连接按钮。已连接时点击整张可用设备卡可手动进入下一采集页面，同时保留连接成功后自动进入下一页的逻辑。
- `CollectionBluetoothProvider` 生命周期结束时释放本流程持有的 `DeviceSession`；进入二级页面和配置变更都会保留 Activity 级实例，不触发断连。恢复的历史设备只作为重新连接候选，不根据 BluetoothKit 的遗留连接推断当前已连接。
- 实时预览、片段采集或连续记录作为当前页时，如果已建立的蓝牙连接意外中断，采集 Activity 弹出不可取消提示。用户可“退出”并停止本地记录、清空二级页面后返回连接记录仪的采集首页，或“重新连接”最近成功设备；重连期间保留当前 Fragment 与返回栈，实时预览和片段采集重发 `StartCollection` 以恢复心电数据，连续记录只恢复蓝牙连接、不重发 `StartContinuous`，成功后关闭提示并在当前页继续，失败时保留提示供再次尝试。连接记录仪首页不显示该提示。
- 扫描仍由 `CollectionBluetoothProvider` 使用 `:foundation:bluetooth` 完成；点击连接后由 `DeviceSession.connect(address)` 重新建立 GATT 并启用固定数据通道，进入实时预览后再由导航宿主旁路发送片段启动指令。页面只调用会话命令并观察波形、指标、诊断和记录状态，不接收或转发 `ByteArray`。实现边界见 `docs/architecture/device-sdk.md`。
- 实时预览分别收集 `ecgWaveforms` 和 `respirationWaveforms`，去除重复帧后批量写入 `:foundation:device-waveform-ui` 的固定容量采样环形缓冲。View 首次创建时从头起笔，数据中断时停在已有数据末尾，恢复后继续当前轨迹。ECG 按 250 Hz、25 mm/s、10 mm/mV 和物理毫米网格平滑扫屏，波形基线位于绘图区垂直中心，1 mV/10 mm 校准脉冲固定在图纸左下角；呼吸保留相同时间轴但不显示心电图纸，按近期范围自动适配高度。页面同时消费最新 `RecorderFrame`，右栏展示六轴原始有符号计数及皮温、湿度、环境温度；六轴量程换算未明确前不标记为 `g`。
- 片段采集以设备每秒一个聚合帧为数据边界；10 秒片段最多写入 10 个聚合帧，避免墙钟起止时刻恰好跨越 11 个包边界。连续记录不设置帧数上限。
- 片段 DICOM 的 Study ID 使用当前 `CLIP-xxxxxxxxxxxx` 采集记录编号；Patient ID 使用用户资料指纹，只有年龄时写 Patient Age 而不伪造出生日期；设备名称写入 Manufacturer，设备 MAC 写入 Manufacturer Model Name。ECG 按 `400/32767 mV/count`、RESP 按 `200/8388607 mV/count` 写入物理标定，Correction Factor 为 `1`、Baseline 为 `0`；当前没有滤波，相关标准 Tag 只保留空值占位。ECG 同时写入 `25 mm/s`、`10 mm/mV` 的固定显示建议，RESP 的 AUTO 纵向增益不固化到文件。
- 片段采集页复用实时预览的设备卡、波形与数据仪表盘，保证 ECG 与六轴、RESP 与环境/人体卡片使用同一组纵向权重并严格对齐。片段时长由 `CollectionConfig.CLIP_DURATION_SECONDS` 统一配置，最小单位为秒，当前联调值为 10；倒计时、环形进度、总时长以及秒/分钟/小时文案均从该配置派生。环形进度按毫秒计算、每 100ms 更新目标值，并通过线性补间连续绘制；时间文字仍按整秒展示。页面头部明确提示“倒计时结束自动进入上传页面”。页面首次进入时处于等待状态，用户点击“开始采集”后才新建本地记录文件并启动倒计时。用户停止后关闭当前本地记录文件、冻结计时并将右侧主按钮切换为“开始采集”，再次开始会新建记录文件并从配置时长重新倒计时；左侧“实时预览”图标按钮返回实时预览，若正在采集则先停止当前本地记录和计时。手动停止和再次开始均不发送设备指令，实时数据流保持不变。倒计时归零后停止本地记录、推进采集检查点，并自动进入分析模块的上传与分析状态页面；自动跳转不等待设备停止指令的回执，设备停止仅作为跳转后的尽力收尾。`AnalysisActivity` 到达后销毁采集 Activity，上传与分析页返回时直接恢复首页，不返回已完成的采集页面。片段计时起点、当前毫秒进度和采集状态由页面 `SavedStateHandle` 保存；本地记录与上传状态不在采集页单独展示。
- 当前设备按协议文档使用大端标量和包含帧头的全帧 XOR。GATT profile 固定为服务 `FFF0`、通知特征 `FFF1`、写特征 `FFF2`，接收类型为 `NOTIFY`；通过标准 CCCD `0x2902` 开启通知，不再依赖服务发现结果选择业务通道。
- 采集流程首页作为 Activity 内返回栈的根页面保留实例；进入实时预览等二级页面时隐藏首页，返回后恢复原 Fragment、ViewModel 和已扫描设备状态，不重新创建首页或触发首次扫描。
- 点击“其他设备”中的设备可将其切换为当前可用设备，动画重点表现被点击卡片向上移动到可用设备槽位，原可用设备直接替换到被点击设备原来的槽位，其他卡片的顺序和位置保持不变。设备信息与连接按钮属于同一张可用设备卡；目标卡片到位后在卡片内部向下展开连接区，完成普通设备卡到完整可用设备卡的转换。其他设备列表按稳定槽位复用卡片，设备摘要区使用统一高度，避免动画交接真实布局时发生二次测量跳动。
