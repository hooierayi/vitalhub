# 首页采集流程

首页以同一个 `sessionId` 展示四个检查点：采集前问卷、连接设备、开始采集、采集后问卷。
`CollectionFlowProvider` 由本模块以 MMKV 实现，并以 ARouter Provider 向首页、问卷和设备模块提供事件状态机。

- 前问卷提交后为 1/4，设备连接成功后为 2/4。
- 片段或连续采集正常结束后为 3/4，并进入采集后问卷；后问卷提交后为 4/4 并返回首页。
- 实时预览是采集阶段的主页面。片段采集和连续记录间可切换；无论其前一页是什么，系统返回和标题栏返回均回到实时预览。
- Provider 只保存“待前问卷、待连接、可采集、待后问卷、已完成”五个检查点；采集模块内的扫描、连接、断开、当前设备及连接事件统一由 `CollectionFlowActivity` 作用域的 `CollectionBluetoothProvider` 管理，首页和采集页面共享同一实例。项目设备筛选、可用设备选择、卡片顺序、流程提示及 `sessionId` 仍由首页自己的 `CollectionFlowHomeViewModel` 管理，Fragment 仅在渲染时组合两份状态。
- 四个检查点通过事件 reducer 推进。重复提交返回已处理结果并保持已有进度；非法或陈旧事件会被拒绝，不会把进度倒退。
- 应用恢复或硬件中断时，“可采集”回退到“待连接”；采集后问卷中断保留 3/4。系统返回和标题栏返回均清空子流程并回到首页。
- AI 分析不属于这四步流程，后问卷提交不自动打开分析页。
- 每个连接记录仪页面实例首次进入时，立即通过 `:foundation:bluetooth` 开始一次 BLE 扫描，离开页面时停止扫描。之后仅用户主动点击刷新时再次扫描；页面恢复前台、连接失败和扫描结束均不自动重启扫描。
- 页面默认仅显示本项目设备；没有连接历史时，第一个符合当前筛选条件的扫描结果作为可用设备。存在最近一次成功连接的设备时，可用设备优先恢复该设备，即使本次尚未扫描到。
- “可用设备”与“其他设备”是互斥分区，两者合并后构成当前筛选下的设备全集；“其他设备”区域独立滚动。连接成功后才推进采集流程，并通过 `:provider:device` 的 ARouter Provider 保存最近连接设备供下次恢复。
- 最近连接设备只缓存 MAC 和设备名称，不兼容读取其他旧字段；恢复时通过 MAC 从蓝牙适配器重新取得系统设备并构造 `BluetoothGattDevice`。广播数据、RSSI 与扫描时间仅使用本次扫描结果。首次恢复时实时检查连接状态，缓存设备卡右上角显示“已连接”或“已掉线”，不使用缓存值推断当前连接状态。
- 扫描期间头部信号图标持续播放扩散动画，刷新图标持续匀速旋转且不可重复点击，扫描结束后停止；“其他设备”仅展示设备信息，连接操作只出现在“可用设备”。
- 可用设备连接成功后，连接按钮切换为红色“断开设备”按钮；主动或被动断开后恢复为连接按钮。已连接时点击整张可用设备卡可手动进入下一采集页面，同时保留连接成功后自动进入下一页的逻辑。
- `CollectionBluetoothProvider` 生命周期结束时立即释放本流程持有的 GATT 连接；进入二级页面和配置变更都会保留 Activity 级实例，不触发断连。首次恢复的“已连接”状态必须同时满足 BluetoothKit 仍持有该连接且系统报告已连接，避免异步断连期间误显示“已连接”。
- 采集流程首页作为 Activity 内返回栈的根页面保留实例；进入实时预览等二级页面时隐藏首页，返回后恢复原 Fragment、ViewModel 和已扫描设备状态，不重新创建首页或触发首次扫描。
- 点击“其他设备”中的设备可将其切换为当前可用设备，动画重点表现被点击卡片向上移动到可用设备槽位，原可用设备直接替换到被点击设备原来的槽位，其他卡片的顺序和位置保持不变。设备信息与连接按钮属于同一张可用设备卡；目标卡片到位后在卡片内部向下展开连接区，完成普通设备卡到完整可用设备卡的转换。其他设备列表按稳定槽位复用卡片，设备摘要区使用统一高度，避免动画交接真实布局时发生二次测量跳动。
